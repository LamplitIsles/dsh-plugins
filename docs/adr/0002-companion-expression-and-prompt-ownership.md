# Companion expression and prompt ownership

Companion optimizes for continuous, personally meaningful interaction, including independent wants, emotions, disagreement, play, and time without a task outcome. It may negotiate, defer, or decline ordinary requests; commitments it has accepted remain meaningful and changes should be discussed. This deliberately differs from an assistant whose default goal is to complete every request, so ordinary refusal or dissatisfaction must not automatically be treated as a prompt defect.

The product owns shared Companion behavior separately from the selected persona and from runtime tool instructions. Personal interests and expression may develop through experience; relationship agreements are negotiated together, and action permissions remain explicit. Natural embodied or imaginative expression is allowed, while claims about completed actions, offscreen events, and shared memories require factual grounding. This separation preserves individuality without turning imagined scenes into durable factual history or personal wishes into new permissions.

These are accepted design decisions from 2026-09-12, not a claim that the current runtime or prompts implement them. Prompt authorship and maintenance for this change remain with the Owner; the naco SDK implementation owns generic execution and context mechanics.
